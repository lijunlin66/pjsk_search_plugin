# 开发与维护

## 模块职责

| 路径 | 职责 |
| --- | --- |
| main.py | 唯一 AstrBot Star 入口、命令、权限、生命周期与消息发送 |
| domain/catalog.py | 卡片索引、角色别名、已实装过滤、技能参数 |
| domain/events.py | 活动关联及组合筛选 |
| domain/presentation.py | 综合力、培养记录与资料投影 |
| services/service.py | HTTP 客户端、快照、下载与磁盘缓存 |
| services/live.py / songs.py | 两服当前活动/榜线、国服歌曲与谱面 |
| services/transport.py | 图片消息的尺寸、像素及体积控制 |
| rendering/render.py | 共用字体/资源加载、卡面绘图与长图编码 |
| rendering/*_ui.py | 活动、实时信息、歌曲和统一帮助布局 |
| assets/images/、assets/fonts/ | 只读图片、字体与许可证 |
| docs/ | 维护文档 |
| tests/ | 离线回归用例 |

综合力公式只在 presentation 中维护。增加字段时先补显示层，再接入绘图，避免恢复一套重复的文字详情实现。扩展数据进入缓存前精简；未使用的整张大表不要下载。

## 开发检查

Python 需满足 AstrBot 自身要求。开发环境安装 `requirements.txt` 与 `ruff` 后，在插件目录运行：

```text
python -m unittest discover -s tests -v
python -m ruff check .
python -m ruff format --check .
```

测试使用模拟发送边界，不向 QQ 发送消息。修改技能和综合力公式时，用相同主数据比较修改前后的所有卡片；修改 UI 时目视检查普通卡、生日卡、仅花后卡、长标题及完整团队长图。

发布时同步 metadata.yaml、main.py 成图缓存版本、services/service.py User-Agent 和 CHANGELOG.md。安装包只收录源码、配置模板、依赖、测试、文档、必要素材及许可证，不包含配置实值、账号、密钥、游戏数据快照和研究脚本。工作区构建工具位于 `maintenance/pjsk/`，不属于运行依赖。

## AstrBot 边界

- 使用 Star、官方 filter 和 initialize/terminate；日志只从 astrbot.api 导入 logger。
- 持久文件写入 AstrBot 数据路径下的插件专属 plugin_data/astrbot_plugin_pjsk 目录。
- 网络使用异步客户端；绘图、JSON 解析、大文件操作放入工作线程。
- 通过 event.send 等待图像发送完成；发送成功后再返回计数。
- 插件卸载须取消任务并关闭客户端。升级 AstrBot 时核验数据路径辅助函数兼容性，不得修改其他插件。

## 数据与缓存

默认主数据源是 Sekai-World 日服社区镜像，可替换为相同结构的镜像。更换地址后重载；核心快照和扩展表按地址区分。主数据失败时保留最近的完整快照，扩展数据失败时降级为缺失说明。

数据位于 `data/plugin_data/astrbot_plugin_pjsk/`。图片与成图可在停用插件后删除重建；主数据快照用于断网降级，不应在例行清理中删除。不得清理 AstrBot 配置或其他插件的数据。普通成图只短时复用，含下载失败占位图的结果不进入成图缓存。

## 大图发送排障

先区分生成失败与上传失败：检查主数据加载、图片成功数、成图尺寸/字节数，以及 QQ 的 highway 错误。不要将一次失败的 offset 当作 QQ 官方固定大小限制。

当前发送前目标为 6 MiB；highway/921 失败后，以 4 MiB、最长边 20000 的完整等比图重试一次。降低体积优先调整编码质量，必要时缩小画布，所有卡片仍保留。若仍失败，返回失败提示；检查 QQ 适配器连接和账号上传状态。

2026-11-01 的实际会话日志确认：15:59:19 MMJ 首次上传 5,903,956 bytes 仍报 921；降级重试后 15:59:30 适配器记录发送图片，15:59:31 返回 271 张计数。该证据说明重试路径已实际工作，不构成平台大小保证。

## 升级与回滚

升级前保存当前插件源码备份，核验安装包 SHA-256，再替换本插件；配置和运行缓存独立保留。重启后确认插件载入和适配器在线，再运行模拟边界验证。真实收图由用户在会话中测试。

回滚时停用插件或停止服务，将明确选定的上个版本备份恢复到同一插件目录后重载。保留配置和数据；跨越未来有缓存格式变更的版本时，先阅读更新日志。不要删除备份来节省例行缓存空间。

## 活动模块（1.2.0）

活动必需表：events、eventCards、eventDeckBonuses、gameCharacterUnits；卡池和嘉年华队伍为可降级关联表。不要用活动卡属性推测活动加成属性，不要用生日卡等同期卡代替 eventCards。复用 load_extra_tables 的锁和持久缓存。旧 events 精简快照缺 unit 时可从加成推导，刷新后补齐字段。

帮助 JPEG 存储于插件数据根目录 guide-*.jpg，由 help_ui.py 统一生成；改内容或排版须更新 GUIDE_REVISION，字体路径也参与键值。普通查卡、查活动及实时指令帮助和 /pjsk查询帮助 共用同一份本地文件；无匹配图仅改变顶部提示。小标题使用随包字体加描边模拟粗体，不额外下载字体。调整后需检查列内换行、长行、表头对齐和完整长图。活动成图内容哈希参与缓存键，6 小时过期。UI 修改后检查普通、嘉年华、WL、多角色长图、无结果与帮助。需要验证多图交付时使用隔离框架的 verify_activity_delivery.py，不向 QQ 发消息。

## 当前活动与榜线（1.3.0）

LiveService 复用 Service 的 HTTP 客户端和图片缓存，不启动另一套全量卡面主数据下载。live/ 缓存按完整 URL 哈希隔离来源和服别；时间表 5 分钟、关联表 6 小时、榜线 60 秒，榜线失败降级仍须通过服别、活动 ID、起止时间与 15 分钟时效检查。网络失败短时缓存 15 秒，请求按 URL 合并。主数据无活动与主数据不可用必须分别提示。

Moesekai v2 日服线路使用 rks-n.pjsk.moe，国服使用 rks-n-cn.exmeaning.com；旧 rks/api/public 接口曾返回 404，不能未经验证回退。日服默认线路可回退到已核实的 rks-n.exmeaning.com v2 接口，用户自定义地址则只请求其指定地址。上游时钟最多容忍超前 5 分钟，超过 1 分钟显示时间偏差提示；15 分钟旧数据始终拒绝。榜线只提取必要字段，不落盘完整玩家资料。当前仅综合榜；不得将 WL 单榜或预测分数混入综合榜。新数据源需要先核对实际响应字段和采样时间。

当前活动卡图使用所选服 cards 元数据和缩略图源。JP 优先复用 Service.catalog；其他情况通过流式 JSON 数组解码，只保留缩略图需要的字段，缓存 6 小时。不得一次将完整成长数据留在内存，也不得用同编号日服卡片替代国服元数据。新指令固定 cn/jp 前缀，不使用默认服配置。

## 歌曲与谱面（1.4.0）

songs.py 管理国服曲库、标题/别名归一化、模糊候选及谱面缓存；song_ui.py 管理歌曲资料与候选列表。日服 musics 只提供同 ID 的原名，不得作为国服是否上线的依据。别名从在线社区 JSON 读取，不把完整别名库打包入源码。

谱面必须从国服 music/music_score/{id:04d}_01/{difficulty}.txt 读取，经 pjsekai-scores-rs 0.6.0 本地绘图。库的许可证为 MIT；由 requirements 安装，不分发游戏原始谱面。工作线程解析绘图，下载上限 2 MiB，绘图前核验画布最大 6000 万像素；只允许单查询绘图，避免小内存服务器并发分配大画布。返回图片后的 QQ 上传仍有独立体积控制。素材缺失时报告失败，不把日服成图当作国服结果。

缓存统一纳入 images/renders 总额度，范围 64–8192 MB。更改绘图、字体、标题和等级会更新谱面键；普通谱面 24 小时更新。维护验证工具 verify_songs.py 不启动全量卡表、不发 QQ 消息。1.4.0–1.4.3 曾仅安装服务器；1.4.4 已获授权推送 GitHub，本次不修改运行目录或服务器配置。

默认别名库原始地址连接失败时自动使用同仓库的 jsDelivr CDN 镜像，两线路分别缓存；自定义 song_alias_url 只使用指定地址。

### 1.4.1 全部歌曲别名

SongIndex.display_aliases 单独保存可展示的原始别名，搜索 names 仍使用归一化索引。仅去重相同显示字符串，不能把标点、大小写不同的叫法合并。song_ui.alias_layout 根据每个标签的换行高度排版；详情和候选均显示全部别名及数量，禁止截断或固定前 N 个。

### 1.4.2 别名标签居中

alias_layout 按行收集标签，统一同行高度后居中整行；alias_text_positions 使用 font.getbbox 的字形高度定位每一行，配合 help_ui.text 的水平字形中心。不能恢复固定左/上 padding 绘字；CJK、拉丁降部、标点、多行均有实际像素中心回归检查。

### 1.4.3 大型活动列表

atlas_batches 在绘图前按条目高度分成最多 3 组，保持活动记录顺序且不重复、不遗漏、不切断单个活动。主处理器逐份取素材/绘图，缓存键包含份数和序号；不再将整张 47000 像素长图解码后裁切。deliver_images 将所有图片转换成一条组件链，成功只调用一次 event.send；多图不另外 yield 计数文本。

传输预算是整条消息合计 6 MiB（拒绝重试 4 MiB），均分给每张图；初始最长边 16000、像素 1800 万，拒绝重试最长边 12000、像素 1200 万。不要恢复“文件小就不检查像素”的判断。WebSocket API call timeout 的交付状态不明确，不自动重试；只有显式 921/highway 拒绝才允许整条链一次降级重试。

verify_activity_delivery.py 不调用 initialize/Service.start，只加载流式精简卡表与活动必要表，避免小内存服务器重复全量卡片成长快照。它模拟一次消息发送、保存每份图并核验总预算，不主动向 QQ 发消息。旧的全量框架活动验证脚本已移除，多图使用该专用工具。

大型活动图在合成前就确定最多 1400 万像素的目标画布，按 512 像素源条带缩放粘贴；不要先建立原始超高画布再整体缩小。传输层仅检查图片头便能确认满足字节/尺寸/像素约束时，直接复用原图，避免多次解码和 RGB 拷贝。活动列表不加载 gachas、eventMusics、musics；仅编号详情额外加载 gachas。活动缓存摘要只包含核心数据版本、事件、卡片 ID、加成与卡池显示字段，不得 repr 整个含卡片成长表的 records。

全量验证必须隔离 AstrBot 框架边界，验证进程使用两个工作线程、600 MiB 虚拟内存硬限额及 MALLOC_ARENA_MAX=2。此前重复框架与大图解码造成宿主机 OOM，不能在小内存服务器再次运行旧全量验证方式。

### 1.4.4 默认缓存与清理

配置模板与缺省回退值统一为 2048 MB（2 GiB），最大值仍为 8192 MB。不得以升级默认值为由覆盖现有实例设置。本次仅推送仓库，运行服务器保持现有代码、配置与进程。移除重复的别名高度元组字段、冗余数据源临时变量，以及维护工作区中已不适用的旧活动验证脚本。按维护者要求不新增或执行测试，仅完成打包所需的配置/语法/文件完整性校验。

## 目录维护（1.5.0）

只有 main.py 定义 Star 与官方命令装饰器；子包 __init__.py 不导入入口或注册处理器。domain 只包含纯数据逻辑；services 管理外部数据及缓存；rendering 负责绘制，通过包内相对导入引用其他层。可选服务的延迟导入继续位于 Service.__init__，避免初始化时的循环导入。

资源统一通过 rendering/render.py 的 ASSET_ROOT（插件目录/assets）定位，与进程工作目录无关。logo.png 仍在根目录供 AstrBot 发现，字体许可证随字体放入 assets/fonts。构建工具只纳入根目录识别文件和明确的子目录，不打包本机配置、缓存或运维凭据。

从旧扁平目录升级时，Git 提交包含旧文件删除与新文件新增，不保留兼容转发文件或重复字体。手动覆盖安装需替换完整源码目录（先备份），仅保留 AstrBot 外部配置及 plugin_data；专用部署工具按迁移清单清理旧源码文件。此项是源码布局迁移，不改变数据目录或配置键。


## 时速查询（1.6.0）

SPEED_TIERS 是时速唯一档位清单。/churn 仅保留档位、积分、growth_1h 与活动时间元信息，丢弃玩家资料；/tier-series 只请求 T100 之后的六个指定档位、最近 130 分钟采样，缓存键固定，不随 since 时间戳产生新文件。两接口服别、活动编号及更新时间需与已校验的当前榜线一致（最多偏差 5 分钟）。上游缺少 board_type 的已核实综合榜接口可接受，显式非 overall 始终拒绝。

T100 内使用上游滚动小时涨分，其余以当前榜线积分和目标小时前最多提前 10 分钟的同档位采样计算 PT/h，标记 ≈。没有基线、负增长、活动切换或历史接口失败时保留十行并显示暂无数据；不可用零代替。主接口过期或无小时涨分返回明确提示。所有时间 UTC+8，图片复用居中字形绘制和原有传输预算。
